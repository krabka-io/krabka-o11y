# krabka-o11y v0.4.0

This is the first supported krabka-o11y release.

Supported compatibility baselines are Loki 3.7.7, Mimir 3.2.1, Tempo 3.0.3,
Pyroscope 2.3.1, Grafana 13.2.2, Prometheus 3.14.0, and Alloy 1.19.2. The
release assets include the immutable compatibility report, an SPDX SBOM,
GitHub provenance and SBOM attestations, and checksums.

Configuration changes: durable Kafka records and Parquet blocks now carry
format version 1. Existing unversioned data is treated as legacy version 1;
there is no operator migration step.

Upgrade by saving the currently deployed image digest, backing up broker and
object-store data, and replacing one role at a time with the release digest.
Wait for `/ready` and query all four signals between replacements. Do not
deploy a tag without its attached qualified compatibility report.

Rollback by restoring the saved digest one role at a time. Version 1 headers
and Parquet metadata are additive, so the preceding qualified image ignores
them and can query the pre-upgrade corpus. Stop if a future release changes
this policy; its release notes must name the migration first.
