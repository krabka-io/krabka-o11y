# Pyroscope query qualification matrix

The pinned Pyroscope 2.3.1 API has **12 RPCs, 63 direct request fields, 70 unique reachable request fields, and five request enums with 16 variants**. The reviewed inventory contains 114 features. Request acceptance, an empty-store transport smoke test, and a paired rejection do not establish successful query semantics. The inventory and execution registry retain those distinctions: [inventory](../qualification/query-language-inventory.json), [evidence registry](../qualification/query-language-evidence.json).

The oracle source is [`7aeaa0ff91e83538b3ff0d09bfefb168bddc022d`](https://github.com/grafana/pyroscope/tree/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d). The local image is `mirror.gcr.io/grafana/pyroscope:2.3.1`, image ID `sha256:718b585ea168a616ca737018dbd1676992db9e5f1084ec4e9cd18f669326f334`; its version command reports the same source revision. The request declarations come from pinned [querier.proto](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/api/querier/v1/querier.proto) and [types.proto](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/api/types/v1/types.proto).

## Architecture bindings

Krabka defaults to the existing v1 query behavior. `--query-architecture=v2` (or `KRABKA_PROFILES_QUERY_ARCHITECTURE=v2`) selects the pinned segment-writer query contract. Embedded queriers use `QuerierState::with_query_architecture`. The setting applies to direct queriers, sharded frontends, and the combined deployment. It changes observable API behavior; it does not change Krabka's storage format.

| Surface | V1 binding | V2 binding |
| --- | --- | --- |
| Stack-filtered `SelectSeries` | Root-first prefix filtering applies. | The pinned frontend ignores `stack_trace_selector`; the full series value remains. |
| Span-series exemplars | The oracle returns `unimplemented`. | The pinned backend returns `unknown` / HTTP 500 for populated SPAN exemplar requests; a no-match request returns `{}` before invoking that backend. The populated failure is a paired rejection, not positive exemplar support. |
| `GetProfileStats` | Returns tenant-wide ingestion/timestamp statistics. | The pinned frontend consults v1 ingesters; segment-writer data produces an empty response. |
| `AnalyzeQuery` | Returns physical query-impact/statistics data. Selector matching is controlled by `query_analysis_series_enabled` (disabled upstream by default); enabled head-series counts use head overlap without per-profile time filtering. The public frontend returns `{}` before query parsing when either time bound is omitted. | The pinned frontend exposes an empty diagnostic stub, including for malformed or omitted query fields. It provides no evidence that the query expression was evaluated. |
| Series aggregation | SUM adds profiles; AVERAGE divides by profile count. | The pinned frontend drops the aggregation field, so SUM and AVERAGE both add profiles. |
| Async Stacktraces | FORCE falls through to the synchronous result; request IDs do not initiate polling. | With the experimental async flag disabled (default), FORCE falls through synchronously. Enabling the flag submits a background query and polls by its returned UUID. Other polling fields are ignored. |

These distinctions are source-bound: [time-series frontend](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/readpath/queryfrontend/query_select_time_series.go), [stats frontend](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/readpath/queryfrontend/query_get_profile_stats.go), [diagnostic stub](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/readpath/queryfrontend/query_stubs.go), [async handler](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/async/handler.go). `--async-queries-enabled` / `KRABKA_PROFILES_ASYNC_QUERIES_ENABLED` enables the v2 async wrapper; embedded queriers use `with_async_queries_enabled`. Local regressions exercise v1 synchronous dispatch, v2 disabled synchronous dispatch, v2 enabled background dispatch, and tenant concurrency zero rejection. The report records both oracle and candidate settings.

## Executable evidence

The tests live in [pyroscope_differential.rs](../crates/profiles/tests/pyroscope_differential.rs). `real_pyroscope_span_profiles_and_query_analysis_match_krabka` plans 113 rows across JSON/protobuf, direct/sharded backends, exact span stacks, merged pprof, unequal Diff sides, and omitted query-analysis bounds. The unsupported upstream v1 Heatmap probe remains in the denominator and cannot count as positive semantic evidence.

`real_pyroscope_v2_request_fields_match_krabka` provisions an explicit `-architecture.storage=v2 -write-path=segment-writer` oracle, disables self-profile ingestion, and provisions a candidate with the v2 query binding. The latest local matrix completed **100 rows across all 12 RPCs**: 90 successful response comparisons and ten paired expected errors. Paired rejections remain negative evidence. Reports are `pyroscope-v2-fields.json` and `pyroscope-populated-rpcs.json` in the test's undeclared outputs. Each RPC row contains a stable method/scenario ID, its exact request, normalized expected/actual outputs, and the classification. Async rows additionally retain exact submission/poll request-response exchanges with their server-generated IDs.

Separate artifacts `pyroscope-v1-aggregation.json` (four cases) and `pyroscope-v2-async-disabled.json` (two cases) check v1 SUM/AVERAGE, disabled query-analysis matching, and the default-disabled v2 FORCE/DISABLED behavior against their own populated oracles.

The populated fixtures provide independent ledgers: primary CPU stacks `main.work = 40`, `main.work → main.hotloop = 100`, total 140; secondary stacks 15 and 35, total 50. Wide-series SUM must produce 190. V1 AVERAGE must produce 95; the pinned v2 frontend ignores AVERAGE and returns 190. Grouping must expose two groups; limit one must select the primary 140-valued group. The report records these expectations and a SHA-256 of the uploaded CPU pprof. The source reassigns push/OTLP profile UUIDs; a profile-ID witness reads the oracle's assigned UUID with its exact 140-valued exemplar, stores the identical pprof in the candidate with that UUID, and then checks selection and absence. Equality never removes profile IDs from exemplar output.

`max_nodes` selects a cumulative-value cutoff. Nodes tied at that cutoff remain visible, so the returned node count can exceed the requested number. Synthetic `other` nodes conserve omitted values; the pprof resolver can also retain an unused `other` location when only its virtual root was marked. Local fixtures independently check ties, distinct-value truncation, inline frames, and total conservation.

Only permitted serialization differences are normalized: unordered labels/result sets, object-ID association resolved to symbols, and DOT styling/header layout. Coordinates, integer counts, exemplar identities, sample values, timestamps, and pprof associations are preserved. Async IDs differ between servers; each submission/poll identity is checked before excluding that generated ID from semantic result equality. The full raw exchanges retain the IDs. Async result normalization reads the same captured successful poll after validating its status, error metadata, and UUID against the submission. A local HTTP control makes a subsequent poll fail and verifies that the recorded result stays exact.

The generated positive-selector suite now constructs a typed selector AST, combines `=`, `!=`, `=~`, and `!~` matchers, and shrinks valid selector subtrees. It starts with the independently verified 140-valued populated control. Rejection generation remains a separate phase and never promotes syntax errors to successful semantic coverage.

## Recording-rule function filters

The nondeprecated [settings API](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/api/settings/v1/recording_rules.proto) accepts and persists `StacktraceFilter.function_name`. A nonempty name matches an exact original function name anywhere in a stack, including inline frames; recursive occurrences contribute the sample once. Empty filters and names use whole-profile totals. Matched label groups with no matching stacks retain zero values. The pinned [observer](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/metrics/observer.go) does not branch on the filter's metric-type field.

[Independent stack and API ledgers](../crates/profiles/src/recording/tests/function_filters.rs) cover these cases, generic function names, tenant isolation, generation conflicts, and create/get/list/update persistence. The existing remote-write retry test also evaluates a function-filtered rule. These recording-rule checks supplement the 12 query-RPC inventory; they are not additional live query-RPC matches.

## Remaining qualification limits

The default/v1 AnalyzeQuery omitted-bound cases require the complete empty frontend response, including for malformed selectors, with populated hot and cold data. Source: [frontend AnalyzeQuery](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/frontend_analyze_query.go#L31-L44). The excluded-time case now requires both backends to return the selector-matching series when the query overlaps the head, even if no individual profile falls within the window. Queries outside the head remain empty. Four backend/transport rows independently check the equal series count. Source: [Head.Series](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/phlaredb/head.go#L498-L532). Physical query-impact accounting has independent hot/cold ledgers: head row/label/symbol capacities, cold Parquet data/footer and symbol objects, distinct block/profile/series counts, and deduplication across overlapping stores. Heap allocator and hash-table bucket overhead are excluded from the resident-capacity model. The source default disables series matching; `--query-analysis-series-enabled` / `KRABKA_PROFILES_QUERY_ANALYSIS_SERIES_ENABLED` enables it for every deployment role. Disabled matching ignores malformed selectors while retaining physical overlap statistics.

Async query specifications, owner leases, heartbeats and completed results use the tenant's admin object store. Ownership transitions use immutable generations with conditional creation, including on a local filesystem. Fresh owners prevent adoption; stale owners are discovered by the background scanner and bounded by the adoption-attempt limit. Successful results use immutable generation objects selected by a conditional metadata update; staged results from a stale owner never become visible. Retention cleanup preserves running queries and their durable specifications and removes expired terminal payloads. One small versioned expiry fence remains per expired query so a suspended upload cannot recreate a visible query after cleanup; later cleanup removes any resumed uploads. Polling does not adopt work. Shutdown cancels and joins workers and fences their result publication. Independent multi-instance tests cover competing scanners, heartbeats, restart, tenant isolation, storage failure, missing/corrupt specifications, bounded adoption, individual orphan ages, corrupt expiry fences and uploads suspended across cleanup.

The reviewed registry, not this table's field names or number of executions, decides feature qualification. Successful v2 responses, v1/v2 ignored fields, paired malformed-input errors, physical-statistics differences, and unsupported upstream features have different meanings. This bounded suite does not establish 100% support for all profile query semantics.
