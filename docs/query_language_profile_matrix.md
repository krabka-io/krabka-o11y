## Architecture bindings

Krabka defaults to the existing v1 query behavior. `--query-architecture=v2` (or `KRABKA_PROFILES_QUERY_ARCHITECTURE=v2`) selects the pinned segment-writer query contract. Embedded queriers use `QuerierState::with_query_architecture`. The setting applies to direct queriers, sharded frontends, and the combined deployment. It changes observable API behavior; it does not change Krabka's storage format.

| Surface | V1 binding | V2 binding |
| --- | --- | --- |
| Stack-filtered `SelectSeries` | Root-first prefix filtering applies. | The pinned frontend ignores `stack_trace_selector`; the full series value remains. |
| Span-series exemplars | The oracle returns `unimplemented`. | The pinned backend returns `unknown` / HTTP 500 for populated SPAN exemplar requests; a no-match request returns `{}` before invoking that backend. The populated failure is a paired rejection, not positive exemplar support. |
| `GetProfileStats` | Returns tenant-wide ingestion/timestamp statistics. | The pinned frontend consults v1 ingesters; segment-writer data produces an empty response. |
| `AnalyzeQuery` | Returns query-impact/statistics data; selector-matching head series are counted when the request overlaps the head, without per-profile time filtering. | The pinned frontend exposes an empty diagnostic stub, including for malformed or omitted query fields. It provides no evidence that the query expression was evaluated. |
| Series aggregation | SUM adds profiles; AVERAGE divides by profile count. | The pinned frontend drops the aggregation field, so SUM and AVERAGE both add profiles. |
| Async Stacktraces | FORCE falls through to the synchronous result; request IDs do not initiate polling. | With the experimental async flag disabled (default), FORCE falls through synchronously. Enabling the flag submits a background query and polls by its returned UUID. Other polling fields are ignored. |

These distinctions are source-bound: [time-series frontend](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/readpath/queryfrontend/query_select_time_series.go), [stats frontend](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/readpath/queryfrontend/query_get_profile_stats.go), [diagnostic stub](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/readpath/queryfrontend/query_stubs.go), [async handler](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/frontend/async/handler.go). `--async-queries-enabled` / `KRABKA_PROFILES_ASYNC_QUERIES_ENABLED` enables the v2 async wrapper; embedded queriers use `with_async_queries_enabled`. Local regressions exercise v1 synchronous dispatch, v2 disabled synchronous dispatch, v2 enabled background dispatch, and tenant concurrency zero rejection. The report records both oracle and candidate settings.

## Executable evidence

The tests live in [pyroscope_differential.rs](../crates/profiles/tests/pyroscope_differential.rs). `real_pyroscope_span_profiles_and_query_analysis_match_krabka` retains its 89 planned rows across JSON/protobuf, direct/sharded backends, exact span stacks, merged pprof, and unequal Diff sides. The fresh local v1 matrix completed all 89 rows: 88 matched and one retained the unsupported upstream Heatmap capability. The unsupported v1 Heatmap probe is excluded from positive semantic matches.

`real_pyroscope_v2_request_fields_match_krabka` provisions an explicit `-architecture.storage=v2 -write-path=segment-writer` oracle, disables self-profile ingestion, and provisions a candidate with the v2 query binding. Its fresh local matrix completed **91 rows across all 12 RPCs**: 82 successful response comparisons and nine paired expected errors. Paired rejections remain negative evidence. Reports are `pyroscope-v2-fields.json` and `pyroscope-populated-rpcs.json` in the test's undeclared outputs. Each RPC row contains a stable method/scenario ID, its exact request, normalized expected/actual outputs, and the classification. Async rows additionally retain exact submission/poll request-response exchanges with their server-generated IDs.

Separate two-case artifacts `pyroscope-v1-aggregation.json` and `pyroscope-v2-async-disabled.json` qualify v1 SUM/AVERAGE and the default-disabled v2 FORCE/DISABLED behavior against their own populated oracles.

The populated fixtures provide independent ledgers: primary CPU stacks `main.work = 40`, `main.work → main.hotloop = 100`, total 140; secondary stacks 15 and 35, total 50. Wide-series SUM must produce 190. V1 AVERAGE must produce 95; the pinned v2 frontend ignores AVERAGE and returns 190. Grouping must expose two groups; limit one must select the primary 140-valued group. The report records these expectations and a SHA-256 of the uploaded CPU pprof. The source reassigns push/OTLP profile UUIDs; a profile-ID witness reads the oracle's assigned UUID with its exact 140-valued exemplar, stores the identical pprof in the candidate with that UUID, and then checks selection and absence. Equality never removes profile IDs from exemplar output.

`max_nodes` selects a cumulative-value cutoff. Nodes tied at that cutoff remain visible, so the returned node count can exceed the requested number. Synthetic `other` nodes conserve omitted values; the pprof resolver can also retain an unused `other` location when only its virtual root was marked. Local fixtures independently check ties, distinct-value truncation, inline frames, and total conservation.

Only permitted serialization differences are normalized: unordered labels/result sets, object-ID association resolved to symbols, and DOT styling/header layout. Coordinates, integer counts, exemplar identities, sample values, timestamps, and pprof associations are preserved. Async IDs differ between servers; each submission/poll identity is checked before excluding that generated ID from semantic result equality. The full raw exchanges retain the IDs. Async result normalization reads the same captured successful poll after validating its status, error metadata, and UUID against the submission. A local HTTP control makes a subsequent poll fail and verifies that the recorded result stays exact.

The generated positive-selector suite now constructs a typed selector AST, combines `=`, `!=`, `=~`, and `!~` matchers, and shrinks valid selector subtrees. It starts with the independently verified 140-valued populated control. Rejection generation remains a separate phase and never promotes syntax errors to successful semantic coverage.

## Remaining qualification limits

The default/v1 AnalyzeQuery excluded-time case now requires both backends to return the selector-matching series when the query overlaps the head, even if no individual profile falls within the window. Queries outside the head remain empty. Four backend/transport rows independently check the equal series count. Source: [Head.Series](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/phlaredb/head.go#L498-L532). Full physical query-impact byte and component/block statistics also require an independent model appropriate to each storage architecture.

Async completed responses and request specs use the tenant's configured admin object store. Pending requests can resume when polled through a fresh querier, and transient result-write failures preserve the spec for replay. Local tests check restart replay, completed persistence, cross-tenant isolation, background failure, and concurrency rejection. The implementation can repeat read-only work when a pending query is polled on another instance; it does not reproduce the upstream distributed lease/adoption scanner or its result-retention cleanup.

The reviewed registry, not this table's field names or number of executions, decides feature qualification. Successful v2 responses, v1/v2 ignored fields, paired malformed-input errors, physical-statistics differences, and unsupported upstream features have different meanings. This bounded suite does not establish 100% support for all profile query semantics.
