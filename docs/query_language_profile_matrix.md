# Pyroscope query qualification matrix

This audit covers the current differential harness, not the entire Pyroscope query contract. The pinned Pyroscope 2.3.1 API has **12 RPCs, 63 direct request-field declarations, 16 reachable request messages with 70 unique fields, and five request enums with 16 variants**. The resulting inventory contains 114 features; execution evidence must be mapped explicitly before changing their qualification status. An RPC accepting a request does not establish the semantics of every field. Sources: [versioned inventory](../qualification/query-language-inventory.json), pinned [querier.proto](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/api/querier/v1/querier.proto), and [types.proto](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/api/types/v1/types.proto).

The source revision is `7aeaa0ff91e83538b3ff0d09bfefb168bddc022d`. The observed local Docker artifacts use image tag `2.3.1`, image ID `sha256:718b585ea168a616ca737018dbd1676992db9e5f1084ec4e9cd18f669326f334`, storage v1, and query-analysis series counting enabled. They show 84 matched populated-suite rows, four intentional divergence rows, and one unsupported-oracle probe. Rows include repeated backend/transport checks, rather than 89 distinct expressions. The separate generated report has 16 passed selector expressions, seed 42, maximum depth three, and zero mismatches, transport errors, or unrun cases. These are local artifacts, not final remote CI qualification: `pyroscope-populated-rpcs.json` and `pyroscope-generated-differential.json` under `bazel-testlogs/crates/profiles/pyroscope_differential_docker_test/test.outputs/`. The populated-RPC test completed all 89 rows, including seven SelectMergeProfile cases on both backends/transports and 12 unequal Diff comparisons on upstream, the direct querier and the sharded frontend. The separate render test passed with an explicit v1 oracle, finite fixture-relative windows and strict comparison of a fractional-second SelectSeries bucket anchor. Dual-mode migration routing and v2 buckets remain unqualified.

Evidence IDs below refer to [pyroscope_differential.rs](../crates/profiles/tests/pyroscope_differential.rs):

- **R:** `real_pyroscope_render_matches_krabka_after_identical_ingest` and its named `assert_*_match` helpers; populated goroutine fixture, live JSON comparisons.
- **S:** `real_pyroscope_series_and_stats_match_krabka_after_identical_ingest`; populated JSON Series/GetProfileStats compatibility checks.
- **B:** `every_querier_rpc_accepts_binary_connect`; all 12 RPCs against a **Krabka-only empty store**, asserting success and protobuf content type. Responses are not decoded or compared with upstream.
- **P:** `real_pyroscope_span_profiles_and_query_analysis_match_krabka`; independently expected span stacks and analysis counts, on both backends in JSON and protobuf.
- **G:** `compare_generated_profile_selector` inside P; positive CPU control plus 16 generated compound selectors, independently expected stacks and values on both backends/transports.
- **M:** `compare_populated_merge_profiles` inside P; seven SelectMergeProfile cases checked against independent symbolized stack/value pairs on both backends in JSON and protobuf, yielding 28 matched rows.
- **D:** `compare_populated_diffs` inside P; unequal CPU profiles in both directions, checked against independent paired stack values, totals and side ticks on upstream, the direct querier and a sharded frontend through JSON and protobuf (12 matched rows).
- **H:** `assert_v1_heatmap_capability`; upstream-only JSON probe expecting HTTP 501 / `unimplemented`, classified as unsupported and excluded from semantic matches.

“Empty” below means a valid request yielding no matches; it does not mean an omitted field, an empty request message, or an HTTP error. B applies to every row as transport-only evidence.

P's excluded-time AnalyzeQuery difference is attributed to pinned v1 `Head.Series` returning selector-matching series within an overlapping head without filtering each profile's time. Both expected counts are asserted, so an upstream behavior change must be reviewed. This remains a compatibility difference despite the harness passing. Source: [Head.Series](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/phlaredb/head.go#L498-L532).

The reachable nested-field and enum gaps must also remain explicit:

- `StackTraceSelector.call_site[].name` has M's matched root-prefix cases. Reordered names, a leaf-only non-prefix selector, and prefixes with repeated frames are absent; general prefix compatibility remains unqualified. `go_pgo.keep_locations` and `go_pgo.aggregate_callees` have no populated comparison, including through Diff.
- `AsyncQueryRequest.request_id` is untested. FORCE has divergent behavior; DISABLED is only represented by omission, not an explicit request/lifecycle comparison.
- `ProfileFormat`: FLAMEGRAPH has stack evidence; PPROF has the coarse R comparison; UNSPECIFIED is exercised by P's default span request. TREE and DOT are untested. Defaults and format variants are not qualified across every RPC.
- `TimeSeriesAggregationType`: SUM is tested; AVERAGE is untested.
- `ExemplarType`: UNSPECIFIED is the SelectSeries default; NONE appears only in local Heatmap smoke. INDIVIDUAL and SPAN have no live semantic evidence, and exemplar contents are not compared for any variant.
- `HeatmapQueryType`: UNSPECIFIED appears in H; INDIVIDUAL only in local smoke; SPAN is untested. No variant has a populated v2 oracle comparison. The pinned [Heatmap API](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/api/querier/v1/querier.proto) requires v2 storage; the present v1 capability probe is not a reason to mark this surface supported.

The comparator negative controls (`profile_semantic_comparators_reject_index_timestamp_and_count_drift`, the tick/point drift tests, and the new `pprof_stack_comparator_rejects_value_and_symbol_association_drift`) demonstrate detection of corrupted expected values; they do not add request-field coverage. Diff's new negative controls retain scalar totals while changing indexed names, name indices and bar values. Across all 12 RPCs, paired malformed-input error comparisons, tenant isolation across the complete RPC matrix, limits that actually truncate results, and exact time endpoints remain outside this evidence.

Next qualification work is to add empty Diff sides and other profile types, provision a pinned v2 Heatmap oracle, and expand field matrices for modern span/trace/profile IDs, general stack selectors, grouping/AVERAGE/limits/exemplars, and positive, empty and malformed time/selector cases. V1 explicitly rejects trace selectors, Stacktraces profile-ID selectors/DOT, and SelectSeries INDIVIDUAL/SPAN exemplars; those capabilities need the correct v2 oracle or separately classified expected errors. Source: pinned [querier implementation](https://github.com/grafana/pyroscope/blob/7aeaa0ff91e83538b3ff0d09bfefb168bddc022d/pkg/querier/querier.go). Each matrix case should name the inventory features it establishes, save independent expected outputs, and retain divergences or unsupported oracle capabilities separately from semantic matches.
