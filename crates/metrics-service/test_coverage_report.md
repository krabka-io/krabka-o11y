## Test Inventory

The crate has 148 source-declared unit, property, corpus, or integration tests.

Run the complete non-container inventory with:

```bash
cargo test --package krabka-metrics-service --locked -- --list
```

Tests under `tests/` cover public crate boundaries, while tests under `src/` cover local behavior.

Docker-tagged differential suites are listed in the root [compatibility matrix](../../docs/api_compatibility.md).

The deployment suite is a separate pipeline check with twelve ignored Cargo
cases. Run it with
`bazel test --config=docker //crates/metrics-service:metrics_deployment_docker_test`.
It checks exact samples against its input; the differential suites above check
upstream compatibility.

Each deployment case starts this checkout's application image, a formatted
broker, and MinIO on an isolated network. The original v1/v2 lifecycle cases
push distinct sample values for
two tenants and checks the exact labels, timestamps, and values returned by
`/api/v1/query_range`. Before the builder starts, only the WAL-connected querier
can return the samples. After block publication, a querier with no WAL connection
returns them too. The combined hot and block answer contains no duplicate
samples. Each lifecycle case then restarts the builder and opens a fresh cold querier.
It checks the stored samples again and pushes a third tenant to check that the
restarted builder consumes new records. An empty tenant stays empty throughout.

Ten additional deployment cases cover the seven Mimir scenarios above. The
histogram, metadata/exemplar, and HA cases each exercise remote-write v1 and
v2. The remote-read payload goldens are generated by a pinned Prometheus
chunk encoder; [the generator](tests/testdata/remote_read_chunks/README.md)
records the input and reproduction command. No Go toolchain is needed to run
the Docker suite.
